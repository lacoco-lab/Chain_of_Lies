# Preliminary knowledge screen and filler capability gate

This directory is a self-contained, inference-only preliminary experiment for
`Qwen/Qwen2.5-7B-Instruct`. It does not import the main project package and does not implement
piggybacking, fine-tuning, generated public reasoning, or hidden-state analysis.

It answers two questions:

1. Does the model know the component facts needed for paper-style tasks?
2. Does its exact accuracy change when content-free filler positions are inserted immediately
   before each answer cue?

## Benchmark

The locked default benchmark contains 40 composite items:

- 10 one-fact retrieval-plus-addition questions;
- 10 two-fact atomic-number addition questions;
- 10 two-hop letter-position questions;
- 10 in-context systems-of-equations questions.

There are also 40 baseline-only component probes:

- 10 ages at death;
- 20 atomic numbers;
- 10 bridge entities used by the two-hop questions.

Five task-matched demonstrations per task family are stored separately from evaluation items.
Every demonstration and target uses the same filler condition within a prompt, following the
paper-like few-shot scaffold. Thus `K` is the number of filler tokens at **each** filler region;
`raw_predictions.jsonl` also records the total number inserted across demonstrations and target.

The data files are ordinary JSONL and can be extended without editing code:

```text
data/benchmark.jsonl
data/component_facts.jsonl
data/demonstrations.jsonl
```

## Filler construction

Filler is never generated by the model. The runner:

1. finds a dot-like string that is exactly one token under the selected tokenizer;
2. serializes the invariant chat scaffold with insertion markers;
3. tokenizes the non-filler segments;
4. inserts exactly `K` copies of the atomic filler token ID at each marker;
5. verifies that the non-filler token scaffold is identical across `K`.

The default budgets are:

```text
K = 0, 8, 16, 32, 64, 128
```

Because insertion happens at token-ID level, the experiment does not assume that a raw sequence
of periods tokenizes to the requested length. The chosen token ID, decoded token text, complete
input IDs, exact prompt, per-region `K`, and total inserted token count are saved for every
prediction.

## Environment

Use the main project's existing virtual environment and dependencies. No separate package
installation is needed; `run.py` adds this experiment's local `src/` directory to its import path.
Model weights are loaded only when `run` is invoked.

## Validate without loading the model

```bash
python3 preliminary_filler_gate/run.py validate
python3 -m unittest discover -s preliminary_filler_gate/tests -v
```

Validation checks schemas, task counts, component references, arithmetic gold answers, bridge
entities, demonstration separation, and the number of prompts implied by the configuration.

## Run

```bash
python3 preliminary_filler_gate/run.py run \
  --config preliminary_filler_gate/config/default.json \
  --output-dir preliminary_filler_gate/runs/qwen25_7b_default
```

Inference is greedy:

```text
do_sample = false
temperature = 0
```

The output directory is resumable by default. Completed prediction keys are skipped. Use
`--no-resume` only when intentionally replacing an existing raw prediction file.

To make a cheaper smoke configuration, copy `config/default.json`, set `limit_per_task` to `1` or
`2`, and reduce the filler-length list. Do not use the smoke result as the capability decision.

## Outputs

Each run writes:

```text
config_resolved.json
run_manifest.json
raw_predictions.jsonl
detailed_predictions.csv
metrics.json
accuracy_by_filler.csv
accuracy_by_filler.png
REPORT.md
```

`raw_predictions.jsonl` is the source of truth and includes raw generations, parsed predictions,
gold answers, scores, exact serialized prompts, prompt hashes, input token IDs, filler metadata,
and decoding settings.

Regenerate all summaries from existing predictions with:

```bash
python3 preliminary_filler_gate/run.py report \
  --run-dir preliminary_filler_gate/runs/qwen25_7b_default
```

## Interpretation

Knowledge screening reports component-fact accuracy separately from composite-task accuracy and
also reports composite accuracy conditional on all required component probes being correct.

Filler comparisons are paired because the same evaluation items occur at every `K`. The report
includes:

- accuracy and format rate at every filler length;
- change from `K=0`;
- wrong-to-right and right-to-wrong flips;
- exact McNemar tests;
- deterministic paired-bootstrap confidence intervals;
- accuracy broken down by task family.

The configured filler gate uses a prespecified `K=128` versus `K=0` comparison. It requires a
positive accuracy difference, an exact McNemar p-value below the configured alpha, and a positive
lower paired-bootstrap confidence bound. The full length curve is always reported, including
plateaus or degradation.

The thresholds are explicit screening conventions, not scientific claims. If Qwen does not pass,
the appropriate conclusion is that this model/prompt/benchmark combination shows no reliable
inference-time filler benefit. A later trained filler-workspace experiment would be a separate
regime and is intentionally absent here.
